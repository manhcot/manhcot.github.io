Module 13 — Endpoint Security

Protect the device itself, then decide whether the device is allowed onto the network.

13.1 Endpoint protection tools

Defence in depth: several controls cover different threats.

Host-based tools

  • Antivirus / antimalware: detects, blocks, and removes malicious software.
  • Host firewall: filters traffic entering or leaving an endpoint.
  • Spam filtering / blocklisting: reduces unwanted email and access to known-bad destinations.
  • AMP (Advanced Malware Protection): detects and analyses suspicious files and malware activity.
  • Disk encryption: tools such as BitLocker help protect data on lost or stolen devices.

Network-assisted tools

  • ESA: Email Security Appliance; email threat protection.
  • WSA: Web Security Appliance; web traffic inspection / control.
  • NAC: Network Admission Control; checks whether endpoints meet network policy.
  • Cisco ISE: combines AAA and NAC policy functions.
Security posture checking: assesses a connecting device's compliance (for example, required security software or updates). Depending on policy, a non-compliant endpoint can be denied or restricted to remediation access.

14.2 VLAN hopping, DTP and double tagging

Switch spoofing / DTP

Attacker tries to negotiate a trunk with a switch port using Dynamic Trunking Protocol (DTP). A trunk can carry multiple VLANs.

Mitigation: configure user ports as access ports and disable DTP negotiation where appropriate.

Double tagging

Attacker crafts a frame with two VLAN tags. Under specific native-VLAN and trunk conditions, one switch strips the first tag and the remaining tag may direct traffic to another VLAN.

Mitigation: do not use the default VLAN as native, keep native VLANs consistent, and disable trunk negotiation on access ports.

interface GigabitEthernet1/0/10
 switchport mode access
 switchport nonegotiate
!
interface GigabitEthernet1/0/48
 switchport mode trunk
 switchport trunk native vlan 999
VLAN hopping targets Layer 2 VLAN separation. Inter-VLAN routing is a Layer 3 function and a different issue.

14.3 Private VLANs (PVLANs)

Isolation within a primary VLAN.

Port typeCommunicationExample

IsolatedCannot communicate at Layer 2 with other isolated or community ports; can reach promiscuous port.Customer endpoint requiring isolation.

PVLAN proxy attacks can exploit communication through a promiscuous port; ACLs can mitigate these attacks.

14.4 DHCP attacks and DHCP snooping

Two attacks; one core mitigation feature.

AttackAttacker actionImpact
DHCP starvationSends many DHCP requests, often using spoofed MACs.Consumes address pool; legitimate clients may fail to get leases (DoS).
DHCP spoofingConnects a rogue DHCP server.Clients may receive malicious gateway, DNS, or other parameters.
DHCP snooping trust model

DHCP snooping marks ports trusted / untrusted, blocks server messages arriving on untrusted ports, and builds a binding table (IP, MAC, VLAN, interface, lease).

ip dhcp snooping
ip dhcp snooping vlan 10
interface GigabitEthernet1/0/1
 ip dhcp snooping trust
interface GigabitEthernet1/0/5
 ip dhcp snooping limit rate 10
!
show ip dhcp snooping
show ip dhcp snooping binding
Trust the path to the legitimate DHCP server, not ordinary user access ports. Trusting the wrong port defeats the protection.

14.5 ARP spoofing, DAI and IP Source Guard

ARP spoofing / poisoning

Attacker sends forged ARP messages claiming the attacker's MAC belongs to another IP (often the gateway). Traffic may be redirected for a man-in-the-middle attack.

DAI — Dynamic ARP Inspection

Intercepts ARP on untrusted ports and validates IP-to-MAC information against trusted bindings; invalid ARP can be dropped and logged.

IP address spoofing

A host uses an IP address it is not authorised to use, potentially impersonating a neighbour.

IPSG — IP Source Guard

Filters IP traffic on untrusted ports using source IP/MAC binding information. It applies to IP packets generally, not only ARP.

Enable DHCP snooping globally
→
Enable on selected VLANs
→
Enable DAI / IPSG
→
Trust only infrastructure ports

ip dhcp snooping vlan 10

DAI commonly relies on DHCP snooping bindings. Static-IP hosts may need appropriate ARP ACL / static-binding planning; otherwise valid ARP may be dropped.

Module 15 — Cryptographic Services: Fundamentals

Focus on what a cipher changes, one-time-pad requirements, and what information an attacker has.

15.1 Substitution vs transposition

Substitution

Replaces a plaintext symbol with another symbol. Example: Caesar shift A → D, B → E.

Transposition

Rearranges symbol positions but does not change the symbols themselves. Example: ABCD → CADB.

Modern cryptography should rely on sound algorithms and protected keys, not on an algorithm being secret.

15.2 One-time pad (OTP)

A correctly used one-time pad can provide perfect secrecy only if every condition is met:

  1. Key is truly random.
  2. Key is at least as long as the message.
  3. Key remains secret.
  4. Key is used once only.
  5. Key is distributed and stored securely.
Reusing an OTP key violates the one-time-use condition and can expose relationships between messages.

15.3 Cryptanalytic attacks

AttackAttacker has / can doMemory clue
Brute forceTries possible keys until a plausible result appears.Try every key.
Ciphertext-onlyHas ciphertext only.Encrypted output only.
Known-plaintextHas plaintext and its matching ciphertext.Known pair.
Chosen-plaintextChooses plaintext and obtains its ciphertext.Choose input, observe encryption.
Chosen-ciphertextChooses ciphertext and obtains decrypted plaintext, within the attack model.Choose encrypted input, observe decryption.
Frequency analysisUses letter / symbol frequencies and language patterns.Statistical patterns.
Meet-in-the-middleStores intermediate results to reduce work on certain multiple-encryption schemes.Search from both ends.
Revision check — Module 15
  1. Which cipher rearranges positions? Transposition.
  2. Name two OTP requirements. Random key, message-length key, secrecy, one-time use, secure handling.
  3. Known vs chosen plaintext? Known is already available; chosen is selected by attacker.

Module 16 — Cryptographic Services

Match each security goal to the mechanism that supports it.

16.1 Security goals

GoalQuestionTypical mechanism
ConfidentialityCan an unauthorised party read the data?Encryption.
IntegrityWas data altered?Hash, HMAC, or digital signature depending on requirement.
Origin authenticationDid it come from expected source?HMAC or signature / authenticated protocol.
Non-repudiationCan the signer plausibly deny signing?Digital signature plus reliable identity and key control.
Hash alone ≠ proof of sender identity. HMAC uses a shared secret; a digital signature uses asymmetric keys.

16.2 Hash, HMAC and keyspace

Cryptographic hash

Maps arbitrary-length input to a fixed-length digest. A secure hash aims to make it hard to reverse the digest or find collisions. MD5 and SHA-1 are legacy for modern collision-resistance needs; SHA-2 and SHA-3 are newer families.

HMAC

Combines a shared secret with a hash construction to provide message integrity and authentication for parties that share the secret. It does not provide public-key non-repudiation.

Keyspace: an ideal n-bit key has 2^n possible values. Adding one bit doubles the keyspace: 2^(n+1) = 2 × 2^n.

Example: 129-bit keyspace has twice as many possibilities as a 128-bit keyspace.

16.3 Symmetric vs asymmetric; block vs stream

FeatureSymmetricAsymmetric
KeysSame shared secret for encryption/decryption.Public/private key pair; operation depends on algorithm and use.
PerformanceGenerally efficient for bulk data.Generally more computationally expensive.
ChallengeSecurely share the secret.Authenticate the public key's identity binding.
ExamplesAES; DES/3DES and RC4 are legacy.RSA; Diffie–Hellman for key agreement.

Block cipher

Processes fixed-size blocks. AES is a modern example; modes determine how blocks are handled.

Stream cipher

Combines data with a keystream. RC4 is historical and considered insecure for modern use.

Diffie–Hellman does not encrypt the entire message. It helps peers establish shared key material over an insecure channel.
Revision check — Module 16
  1. Confidentiality mechanism? Encryption.
  2. What does HMAC provide? Integrity and authentication between shared-secret holders.
  3. Does plain hash prove sender identity? No.
  4. Effect of one extra key bit? Doubles keyspace.
  5. Efficient bulk encryption? Symmetric encryption.

Module 17 — Public-Key Cryptography and PKI

Public/private keys, digital signatures, and certificates work together to establish trust.

17.1 Digital signatures

Simplified digital-signature flow
  • Sender signs using sender's private key.
  • Receiver verifies using sender's public key.
  • Signature supports integrity and authentication; non-repudiation also depends on identity and private-key control.
  • A signature does not automatically make the message confidential.

Revision check — Module 17
  1. Which key signs? Sender's private key.
  2. Which key verifies? Sender's public key.
  3. CA vs RA? CA issues/signs; RA helps verify identity / process requests.
  4. CRL vs OCSP? Revoked-certificate list vs online status query.

Module 18 — VPNs

VPNs protect communication over untrusted networks. IPsec operates at the IP layer.

18.1 VPN topologies

Remote-access VPN

A single remote user / device securely connects to an organisation's network, using client software or another supported remote-access method.

User → network

Site-to-site IPsec VPN

Gateways protect traffic between networks. Sending gateway encapsulates / encrypts; receiving gateway decrypts and forwards into destination LAN.

Network → network

18.2 IPsec functions, AH and ESP

Function / protocolWhat it providesImportant note
ConfidentialityEncryption prevents unauthorised reading.ESP commonly provides it.
IntegrityDetects changes to protected data.Uses integrity algorithms / authenticated encryption.
Origin authenticationChecks expected peer identity.IKE can use PSKs or certificates.
AH — Authentication HeaderIntegrity and origin authentication for protected IP fields.No confidentiality; NAT can conflict with AH integrity.
ESP — Encapsulating Security PayloadConfidentiality and can provide integrity / authentication.Commonly used for VPNs.
Diffie–HellmanEstablishes shared secret material over insecure channel.Choose suitable DH group.

Transport mode

Protects the payload of the original IP packet while the original IP header remains the outer IP header. Often host-to-host.

Tunnel mode

Encapsulates the entire original IP packet in a new packet with a new outer IP header. Common gateway-to-gateway mode.

Conceptual packet layout; exact fields depend on protocol and configuration.

18.3 IKE phases — classic IKEv1 course model

Phase 1
Authenticate peers and establish protected IKE / ISAKMP channel.
→
Phase 2
Negotiate IPsec SAs / parameters for protected data traffic.
→
Data transfer
ESP / IPsec protects matching traffic.

Phase 1 proposal fields commonly include encryption, hash / integrity, authentication, DH group, and lifetime. Phase 2 negotiates IPsec SA / transform parameters and traffic selectors.

Memory cue: Phase 1 protects negotiation; Phase 2 establishes IPsec protection for user data. This is the classic IKEv1 model; IKEv2 has a different exchange structure.
Revision check — Module 18
  1. Which VPN connects sites? Site-to-site.
  2. Which protocol encrypts? ESP.
  3. Which mode wraps the original IP packet? Tunnel.
  4. Diffie–Hellman role? Establish shared secret material.
  5. Phase 1 vs Phase 2? Protect/authenticate IKE; then negotiate IPsec SAs.

Module 20 — Cisco ASA: Introduction

Understand ASA roles, interface security levels, and the direction of traffic.

20.1 ASA role and security levels

  • ASA can provide stateful firewalling, NAT, VPN, routing, and related security functions.
  • Routed interfaces have security levels from 0 to 100.
  • Typical convention: inside = 100, outside = 0, DMZ = intermediate.
Typical ASA interface security-level model
DirectionTypical default conceptExample
Higher → lowerGenerally allowed by default in classic ASA model unless other policy blocks it.Inside to outside.
Lower → higherNot automatically allowed; explicit policy / ACL generally required.Outside to inside.
Same security levelDo not assume communication is allowed; it depends on configuration.Verify settings.
Security levels are not a replacement for understanding ACLs, NAT, connection state, and ASA version/configuration.

20.2 Setup checklist

  1. Identify interfaces and assign names such as inside, outside, dmz.
  2. Set interface IPs and appropriate security levels.
  3. Configure routing.
  4. Configure NAT according to design.
  5. Apply access rules for traffic that must be explicitly permitted.
  6. Restrict management access and prefer secure management protocols.
  7. Verify interface state, routes, NAT, ACLs, and active connections.

Module 21 — Cisco ASA: Configuration

Learn the configuration building blocks and the difference between defining a rule and applying it.

21.1 ASA access control lists

ACL entries define which traffic matches a rule. An ACL created but not applied to an interface may not affect traffic as intended.

Important syntax distinction: ASA ACL examples commonly use a subnet mask (e.g. 255.255.255.0) after a network address, unlike classic IOS ACL wildcard masks (e.g. 0.0.0.255). Follow your course's ASA syntax.
! Illustrative ASA-style example
access-list OUTSIDE-IN extended permit tcp any host 10.10.10.20 eq 443
access-group OUTSIDE-IN in interface outside
!
show access-list
show running-config access-group

Direction: in interface outside evaluates traffic entering the ASA through the outside interface.

21.2 Network objects and object groups

Network object

Names a host or subnet. Reuse improves readability and maintenance of ACL / NAT policy.

Object group

Groups multiple hosts, networks, services, or ports so policy can be expressed efficiently.

object network INSIDE-NET
 subnet 10.10.10.0 255.255.255.0
!
object network WEB-SERVER
 host 10.10.10.20
